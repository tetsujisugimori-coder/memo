## 受信から保存まで

`submit_text_preview` → 既存stdio MCP → Adapter token付き `POST /text` → メモリ内一時キュー → ブラウザの「受信を確認」 → `textContent`による未保存原文プレビュー。

受信・再取得・プレビュー・破棄では保存処理を呼ばない。`submit_dummy_preview` と固定fixtureは維持し、固定ダミーの保存ボタンは無効。

ユーザーが「新規メモとして保存」を押したときだけ、Browser token付き `POST /begin` がサービス側で新規UUIDと保存計画を発行する。保存先は既存 `resolveNewNoteCollection()` による選択中コレクション（全体・ゴミ箱等なら未分類）を事前表示し、表示した保存先を使用する。保存開始後の再試行は最初の保存先を維持する。削除された保存先へ別の場所を自動選択しない。

アプリはWeb Locksで同じ保存領域内の同ID操作を直列化し、既存 `getStoredNoteSnapshots()` でコミット済み結果を照合する。未作成なら既存 `createNote(title, body, { id, collectionId })` → `putNote()` を利用。`putNote`はIndexedDB transactionの `oncomplete` 後に成功を返す。独自保存形式・DB・永続キューは追加しない。同名タイトルは既存 `uniqueTitle()` で番号を付ける。本文は送信文字列のまま渡し、trim・HTML変換・Markdown再生成を行わない。

保存成功後の `POST /complete` で保存済みに移行する。MCP再送応答の `saved: true` はブラウザから完了通知を受けた既存結果であり、そのMCP呼び出しが保存した意味ではない。初回受信は `state: queued, saved: false` で、ブラウザ表示・保存の成功を表さない。

## MCP呼び出し例と契約

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "submit_text_preview",
    "arguments": {
      "requestId": "de8ad49a-ea46-4c9c-a02d-021637cbd6db",
      "title": "AIからの確認用メモ",
      "body": "日本語本文\n\n- 箇条書き\n\n`inline code`\n\n```js\nconst value = 1;\n```\n"
    }
  }
}
```

- `requestId`: 呼び出し側生成の小文字UUID v4。再送では同じIDと同じtitle/bodyを使う。
- `title`・`body`: 必須の文字列。空文字・空白のみは拒否。検証でtrimを使うが受信文字列は変更しない。
- `title`: 最大200 Unicodeコードポイント。
- `body`: 最大65,536 Unicodeコードポイント、かつUTF-8で65,536 byte。両上限を満たす必要がある。
- `/text` のJSON受信上限: 409,600 byte。制御文字のJSONエスケープ分も含む。既存 `/dummy`・ブラウザ制御ルートは従来どおり1,024 byte。
- stdio MCP入力バッファ上限: 413,696 byte（ツール引数JSON上限とメタデータ等の余裕4,096 byte）。上限を超える入力は接続を終了する。
- 引数は上の3項目だけ。既存メモID・保存先・添付・Report構造・更新・削除等は拒否。標準 `params._meta` の対応は維持し、受信内容や保存計画へ流用しない。
- 不正入力はキュー登録前に拒否。MCPスキーマ違反は `-32602`、同IDの内容競合は `isError: true, state: request_id_conflict`。既存レコードを置き換えない。

## 重複防止・期限・失敗

一時キューは従来どおり1枠、履歴128件、通常の未処理要求は受信から10分で期限切れ。満杯拒否・破棄・期限切れ・保存済みの履歴をサービス終了まで保持し、履歴上限では新規要求を拒否する。履歴を追い出してIDを再登録することはない。

保存開始後の `saving` / `save_failed` は再試行用にサービス終了まで保持し、元の10分TTLでは消さない。この間は他の新規要求が満杯になる。保存済み・破棄済みIDの同内容再送では未処理に戻さない。

保存中はボタン連打と閉じる操作を抑止。失敗では成功表示を出さず本文と固定IDを保持する。基盤が失敗した場合はbrowser-only `POST /failed` で再試行・破棄可能にする。接続が失われて通知できない場合は `saving` のまま再接続・再試行する。

再試行は同じIDの保存済み内容を照合し、二重作成しない。不一致・削除済みなら上書きせず停止。transaction完了後にUI処理が失敗したケースや完了通知の応答消失も同IDの既存結果へ戻す。**破棄は受信内容のみで、既に作成されたメモを取り消さない。** 保存操作中の破棄は禁止。

保証範囲は**同じサービスの継続稼働中、同じOrigin・ブラウザ保存領域内**。タブ再読込・トークン再入力ではキューと固定IDが保持される。サービス再起動でキュー・全履歴・保存計画は失われ、同IDの再投入にも重複防止を保証しない。別Origin・別プロファイル・別端末の保存領域をまたぐ重複防止は保証しない。ローカル実証ではサービス1つに同じ検証プロファイルを使用する。

既存アプリにメモリDBへ自動切替する保存経路はなく、IndexedDB起動失敗は既存起動ガード・エラーに従う。保存領域が使えない場合は成功扱いにしない。通常保存成功は「ブラウザ内に保存」と表示し、private browsingの終了後も残ることやローカルフォルダー同期完了を保証しない。既存保存注意表示をプレビューにも表示する。Web Locksが使えない環境では安全に失敗し、独自の並行保存経路を作らない。

## 表示・接続制限

プレビューは既存 `textContent` と `pre` を使用。リンク・画像要素を生成しない。HTML、script、img/onerror、外部URLは文字列で表示され、プレビューで自動アクセスしない。保存後は既存のMarkdown表示を使用し、HTML風本文のコードが実行されないことを検証する。

待受 `127.0.0.1:8791`、許可Origin、Host/ヘッダー制限、別々の専用Browser/Adapter token、接続数・rate limitは維持。Adapterは `/dummy` / `/text` だけで、browser-onlyの保存状態ルートを呼べない。保存状態ルート自体はDBへ保存しない。MCPにボタン操作を省略する保存ツールはない。

PR-1のSecure MCP Tunnel成功はユーザーによる固定ダミーの実証。PR-2もローカル実証で、OAuthは未解決・未実装。認証完成・一般公開対応済みとは扱わない。
