# Memo-Nexus Web Clipper

Chrome / Edge 共通の Manifest V3 拡張です。現在の展開読み込み版はローカル開発版`0.3.5`で、すべて保存前の確認画面を経由します。

## クリップ方式

- **選択部分**: 選択文と出典情報を保存します。選択範囲のHTMLを取得できる場合は、その中の画像候補も本文位置とともに渡します。選択がある場合の初期値です。
- **ページ全文**: `article`、`main`、`role=main`を優先して本文を抽出し、安全なMarkdownへ変換します。本文中の画像候補は位置マーカー、alt、キャプション、元URLを保持します。画像本体は記事ページではなく拡張のService Workerで取得し、確定結果を本文と一緒に本体へ渡します。本文と画像はURLフラグメントに載せません。
- **リンクのみ**: 本文なしで出典、URL、取得日時を保存します。選択文がない場合も、この方式を明示的に選んだ時だけ利用します。
- **メモ付き**: 選択文（なければリンク情報）へ短いユーザーメモを付けます。

画像のOCR、要約、スクリーンショット取得、PDF、Safari/iPhone/iPadは対象外です。ページ全文の抽出は汎用的な候補選択であり、サイト固有の完全な再現はしません。

## 開発版のインストール

1. Memo-Nexus本体を `http://127.0.0.1:5500/` で開けるようにします（`localhost`ではなくこのURLを使います）。別のURLを使う場合は下記設定を先に変更します。
2. Chrome は `chrome://extensions`、Edge は `edge://extensions` を開き、開発者モードを有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」を選び、この `extensions/web-clipper` フォルダを指定します。
4. 本体側の `web-clipper-config.js` に利用する拡張IDが登録されていることを確認します。
5. 本体ページを再読み込みします。

ポップアップ上部にはmanifestから取得した拡張バージョンと、現在の接続先・配布方式を表示します。ローカル開発版の更新方法は「開発版の更新確認」を参照してください。

## 接続先の設定

- 拡張の開発URL・本番URL: `config.js` の `targets`
- 配布方式と配布方式ごとの初期接続先: `config.js` の `distributionChannel` と `distributions`
- 拡張に許可するURL: `manifest.json` の `host_permissions`
- 本体が受信を許可する拡張ID: 本体ルートの `web-clipper-config.js` の `allowedExtensionOrigins`

開発環境の既定接続先は `http://127.0.0.1:5500/` です。URLを変更する場合は`config.js`を更新し、拡張IDを変更した場合は本体の設定も更新します。`<all_urls>`、`file:`、ブラウザ内部ページの権限は使いません。選択情報の取得には、ユーザーが拡張アイコンを押したタブだけに一時的に与えられる`activeTab`権限を使います。

接続先（development／production）と配布方式（ローカル開発版／Edgeアドオン版）は別の概念です。選択した接続先は`chrome.storage.local`へ保存されますが、接続先変更で配布方式は変わりません。現在の`distributionChannel: "unpacked-development"`はproductionへ接続してもローカル開発版であり、Edge自動更新とは表示しません。受信データには拡張バージョン、Manifestバージョン、ブラウザ種別、接続先、配布方式を含めます。

## 展開読み込み版の更新方法

GitHubでPRをマージしても、PC内へ展開読み込みした拡張機能は自動では更新されません。実機では次の順で更新します。

1. PC内のMemo-Nexusリポジトリを`git pull`で最新化します。
2. Edgeで`edge://extensions`を開き、Memo-Nexus Web Clipperカードのバージョンを確認します。
3. `0.3.5`より古ければ、そのカードの「再読み込み」を押します。
4. 再読み込み後も版数が変わらない場合は、Edgeが別フォルダを参照している可能性があります。古いMemo-Nexus Web Clipperを削除し、現在のMemo-Nexusリポジトリの`extensions/web-clipper`フォルダを「展開して読み込み」で登録し直します。
5. 再登録後は拡張機能IDが変わることがあります。Memo-Nexusの「設定 → データ管理 → Web Clipper」で許可済みIDを確認し、表示されたIDを登録します。

ポップアップ上部の「拡張機能バージョン」は、現在Edgeが実際に読み込んでいるmanifestの値です。`0.1.0`などが表示される場合は、このリポジトリの`extensions/web-clipper`ではない古い展開読み込み版を使っている可能性があります。

## 再クリップと画像の再試行

同じ記事URLをもう一度クリップすると、確認画面に既存のWebクリップが表示され、既定でそのメモを更新します。更新ではメモID、コレクション、フラグ、クリップと無関係のメタデータを維持し、本文・出典・クリップ画像だけを新しい取得結果へ置き換えます。複数の同一URLがある場合は対象を選ぶか、新しいメモとして保存できます。URL比較では`#fragment`と末尾スラッシュの差だけを同一扱いにし、queryは保持します。

画像の取得に失敗した場合、確認画面の「失敗した画像だけ再試行」は元URLを使って拡張機能のService Workerへ再依頼します。成功済み画像は再取得しません。ログイン必須、期限切れのURL、アクセス拒否、タイムアウト、容量上限、非対応形式などは理由を表示します。再試行できない場合も「画像なしで保存」で本文だけを保存できます。

ローカル開発版かつ接続先が開発環境の場合だけ、ポップアップを開いた直後に開発サーバー上の`manifest.json`を確認し、有効な転送がなければ一度だけ再読み込みを試みます。production接続ではこの確認を行わないため、上記の手動手順を使います。

転送データは共通設定の10分TTLで検証します。期限切れ、`createdAt`欠落、不正なclipは更新確認時にそのキーだけ自動清掃し、`window.open()`失敗またはACKタイムアウトでも今回の転送キーだけを削除します。10分以内の正常な転送が1件以上ある場合だけ更新を延期します。

開発サーバーが停止している場合は小さな診断だけを表示し、更新確認を省略して通常のクリップ機能を続けます。同じ対象バージョンを再読み込みしても現在版が変わらない時は自動処理を繰り返しません。「Edgeが別の拡張機能フォルダを読み込んでいる可能性があります」と表示された場合は、拡張管理画面でこのREADMEのある`extensions/web-clipper`フォルダが読み込み元か確認します。サーバー側のmanifestがさらに新しい版へ上がった時は、その版について再び一度だけ自動更新を試します。

## 本番版の公開と更新

本番接続を選ぶだけではEdgeアドオン版になりません。将来ストア提出用パッケージを作る際は、パッケージ作成時に`config.js`の`distributionChannel`を`edge-store`へ切り替えます。`distributions.edge-store.defaultTarget`はproductionなので、初回起動時にlocalhostへ向きません。この配布設定は利用者の接続先選択では書き換えません。手作業の切替箇所はこの1項目ですが、正式なパッケージ工程を導入する際は同項目を生成設定にします。

Edgeアドオン版では独自の定期更新、起動ごとの`chrome.runtime.requestUpdateCheck()`、無条件の`chrome.runtime.reload()`を行いません。実行コードをGitHub Pagesなどから動的に読み込むこともせず、Edgeアドオンの標準更新機構へ任せます。判定用の`management`権限は使用しません。

本番公開時はEdge Partner Centerへパッケージを登録し、必要に応じて検索非公開の`Hidden`として専用URLを知る利用者だけへ配布できます。更新するたびに`manifest.json`のバージョンを上げて新しいパッケージを再提出し、審査・公開後の配信はEdgeに任せます。現時点ではストア登録・ストア経由の自動更新を確認済みとはしていません。

拡張機能のJavaScript、HTML、CSS、manifest、または`config.js`を変更するPRでは、必ず同じPRで`manifest.json`の`version`を上げ、このREADMEの表示版数と更新案内も対応させます。

記事と別ホストのCDN画像もCORSに依存せず取得するため、Service WorkerにはHTTP/HTTPS画像へのhost permissionが必要です。権限は`http://*/*`と`https://*/*`だけに限定しています。Chrome／Edgeで初めてインストールする時、またはこの権限を追加した版へ更新・開発版を再読み込みした時に、サイトアクセス権限の確認が表示された場合は許可してください。画像取得時の追加ポップアップはありません。

SVGとAVIFは生データを本体へ渡さず、必要時だけ作るOffscreen Documentで安全なWebP（非対応時はPNG）へラスタライズするため、`offscreen`権限を使います。Offscreen Documentは記事ページとは分離され、SVGのスクリプト、イベント属性、`foreignObject`、外部画像・フォント参照を除去してから変換します。

## 動作確認

1. 任意のWebページで日本語の文章を選択し、拡張アイコンを押します。
2. ポップアップに選択有無、タイトル、URLが表示されることを確認します。
3. 接続先を選び「Memo-Nexusで確認する」を押します。
4. 本体の確認画面でタイトル、本文、コレクション、画像候補を確認します。画像は個別または全選択・全解除で保存対象を変更できます。保存前に自動保存はされません。
5. 選択なしでも同じ操作でURLクリップ候補を開けます。

本文は通常のURLパラメータへ入れません。選択した接続先の `?web-clip=1#clip=<base64url>` のフラグメントへUTF-8のbase64url形式で入れます。フラグメントはGitHub Pagesを含むサーバーへのリクエストに送信されません。本体は起動判定を保持して確認画面を一度だけ開き、成功・失敗にかかわらず`history.replaceState()`でフラグメントと`web-clip`だけをURL・履歴から削除します。ほかのクエリは維持するため、確認画面を閉じた後や保存後にページを更新しても空の確認画面は再表示されません。旧来の`postMessage`受信経路とアプリ内の手動起動は維持します。

## 画像の保存仕様

- ロゴ、広告、ナビゲーション、SNS、プロフィール、追跡ピクセル、小さすぎる画像を属性・周辺要素・実寸で候補から除外します。URLを重複排除し、`article`／`main`内、`figure`／`figcaption`付き、十分な実寸の画像を優先してから20件上限を適用します。
- `currentSrc`、`srcset`、`data-src`、`data-lazy-src`、`data-original`を確認し、取得可能なHTTP(S)画像を選びます。
- 1画像5MB、最大20画像、1クリップ合計20MBです。本体保存時も既存添付の1メモ合計20MB制限を再確認します。
- URL拡張子ではなく、HTTP `Content-Type`、画像のマジックバイト、実デコードを基準に判定します。`application/octet-stream`でもJPEG、PNG、WebP、GIFの実体を判定できれば保存できます。
- GIFは先頭署名と縦横サイズを検証し、アニメーションを維持するためCanvas圧縮を通さず元データのまま保存します。SVGは危険な要素・属性・外部参照を除去してWebP／PNGへ、AVIFはブラウザがデコードできる場合にWebP／PNGへ変換します。変換後のMIME、容量、寸法と元MIMEを保存情報へ反映します。
- ポップアップからService Workerへ画像ごとのリクエストIDを付け、最大3件ずつ取得します。`runtime.lastError`、HTTP、権限、MIME、デコード、変換、容量、タイムアウトを画像単位で確定し、1件の失敗で他画像を止めません。
- 保存済み画像は通常の画像ブロックと同じIndexedDB、表示、拡大、削除、エクスポートを使います。確認画面で除外した画像は本文から外します。取得失敗画像は元位置に理由付き注記を残します。選択画像のIndexedDB保存に失敗した場合はメモを作成せず確認画面を維持し、再試行または明示的な「本文のみ保存」を選べます。

## 制約

- 認証必須画像、期限切れURL、アクセス元を検査するCDN、`blob:` URLは取得できない場合があります。CORS制約はService Worker取得で回避しますが、HTTPエラーやタイムアウトは画像単位の確定状態として表示します。
- ページ全文は記事本文候補を抽出しますが、サイト固有のレイアウトを完全に再現するものではありません。
- AI要約、OCR、スクリーンショット取得は未対応です。AVIFをデコードできないブラウザ環境では、その画像だけ変換失敗として除外します。
- iPhone / iPad のSafari拡張には未対応です。
- 長い選択本文はブラウザやOSのURL長上限に依存します。上限を超える場合はクリップできないため、範囲を短くして再実行してください。
